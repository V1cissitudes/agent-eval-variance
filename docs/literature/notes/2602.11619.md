# 2602.11619 When Agents Disagree With Themselves: Behavioral Consistency as an Uncertainty Signal for LLM Agents

- ICML 2026 Workshop（Statistical Frameworks for Uncertainty in Agentic Systems）｜ https://arxiv.org/abs/2602.11619
- 阅读：2026-10-03，基于 arXiv HTML 全文的要点提取（数字为原文引用）；细节以原文为准。

## 设置
- 模型：Llama 3.1 70B、GPT-5、Claude Sonnet 4.5、Gemini 3 Pro，全部经云 API 调用。
- HotpotQA validation（distractor）200 题 × 10 次 × 4 模型 = 8,000 次运行；另有 SWE-bench 50 任务 × 5 次。
- ReAct，三个工具：Search(query)、Retrieve(title)、Finish(answer)；HotpotQA 轨迹 3–8 步。
- 主实验 T=0.7（Gemini 需额外设 top_p=0.95 才真正随机）；温度消融 T ∈ {0, 0.3, 0.7}（20 题 × 5 次）。

## 度量
- 一致性 = 给出众数答案的运行比例；行为分歧 = N 次运行中不同动作序列的数量；步数变异 (max−min)/mean；首次分歧步。

## 主要结果
- 每题 10 次运行产生的不同动作序列：Claude 2.3、GPT-5 2.4、Gemini 3.2、Llama 4.2。
- 一致题（≤2 条序列）准确率 82–87%，不一致题（≥4 条）41–65%；Mann-Whitney 全部 p<0.001。
- k=3 一致投票的选择性预测：87–88% 准确率、54–62% 覆盖率，比单次运行高 6–14 个百分点。
- **29.3% [28.4–30.1%] 的单次运行评测会给出错误的模型排序**（bootstrap 10,000 次）。
- T=0 时 Claude/Gemini 接近 1 条序列，Llama 仍有 2.3 条 → 分歧不只来自采样。

## 局限（作者自述 + 评述）
- 只用 API 模型，**服务端配置（缓存、批处理、精度）不可控也不可见**；作者承认无法排除提供方的 prompt caching。
- 没有方差分解：只有"一致 vs 不一致"的对比和相关分析，没有把方差归到题目/模型/种子/服务配置。
- 没有回答"需要重复多少次"，只说明了单次运行不可靠（29.3% 排序错误）。

## 对本项目的意义
1. **最直接的前人工作，同一数据集同一设置**（HotpotQA distractor validation）→ 我们可以直接对比，并引用其"29.3% 排序错误"作为动机。
2. **我们的增量**：本地开源模型、可控服务栈（缓存/精度/批处理）、方差成分分解、重复次数与题数的功效分析。
3. **应补的度量**（为可比性）：每题不同动作序列数、首次分歧步——我们的轨迹已记录每步动作，可在分析脚本里直接计算。
4. 他们的工具多一个 Retrieve(title)；我们只有 search。写论文时需说明这一差异。

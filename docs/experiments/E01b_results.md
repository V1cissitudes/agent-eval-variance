### H3：开缓存时，精度越低越不一致？（预登记）——**不成立**
- Cochran–Armitage 趋势检验（得分为位数 16/8/4，双侧）：greedy p = 0.17，qwen p = 0.32（第一对 p = 0.25，之后各对 p = 0.89）。方向与假设相反：两档量化的不一致率都**低于** BF16，而且不单调（FP8 最低）。
- 按题目重抽样的"量化 − BF16"分歧率差值（95% 区间，考虑题内相关）：greedy FP8 −3.3 pp [−7.3, +0.3]、AWQ −2.3 pp [−6.3, +1.7]；qwen FP8 −1.3 pp [−3.0, +0.4]、AWQ −0.7 pp [−2.4, +1.0]。区间都包含 0，没有证据表明量化放大了服务器内的缓存分歧。
- 关缓存时三档的不一致都是 0，精度 × 缓存的 logistic 交互不可估计（已登记的偏离），只报告计数与上界（上表）。

**"第一对 vs 之后各对"在三档精度下都复现**（E01a 的探索性发现）：

| | 第一对（greedy / qwen） | qwen 之后各对 |
|---|---|---|
| BF16 | 8.3% / 8.7% | 12/600 = 2.0% |
| FP8 | 5.0% / 5.7% | 9/600 = 1.5% |
| AWQ | 6.0% / 6.7% | 12/600 = 2.0% |

### D-study：比较不同精度时，题目才是瓶颈
精度对比的题目 × 条件交互方差远大于 E01a 中的对比：温度 0.7 下 BF16 vs FP8 为 0.026–0.029、BF16 vs AWQ 为 0.082–0.092，是 E01a 缓存、采样方案对比（≤ 0.0023）的 11–40 倍；贪心下 BF16 vs FP8 为 0.071–0.082、BF16 vs AWQ 为 0.126–0.135，是 E01a greedy 缓存关 vs 开（0.023）的 3–6 倍。

| 对比（检测 3 pp，双侧 α=0.05，种子独立） | 100×1 / 300×1 / 300×3 / 300×5 | 1000×1 | 300×1 排反概率 |
|---|---|---|---|
| BF16 vs FP8，greedy（关 / 开） | 0.17–0.18 / 0.42–0.44 / 0.44–0.47 / 0.44–0.48 | 0.89–0.91 | 3.5–4.0% |
| BF16 vs FP8，qwen（关 / 开） | 0.17–0.19 / 0.41–0.46 / 0.67–0.69 / 0.75 | 0.89–0.93 | 3.1–4.1% |
| BF16 vs AWQ，greedy（关 / 开） | 0.13 / 0.28–0.29 / 0.29–0.30 / 0.29–0.30 | 0.71–0.73 | 7.8–8.3% |
| BF16 vs AWQ，qwen（关 / 开） | 0.12–0.13 / 0.28–0.29 / 0.35–0.37 / 0.37–0.40 | 0.70–0.72 | 8.1–8.6% |

- 每题多跑几次几乎不提高功效：交互方差属于题目层，只有增加题目才能降下来。比较 BF16 和 AWQ 时，即使每题 5 次，300 题的功效也只有约 0.3–0.4；1,000 题 × 1 次约 0.7。
- 种子配对在这里帮助很小（例如 BF16 vs AWQ qwen 关，300×1：配对 0.28，独立 0.28），因为噪声主要不来自采样。
- **方法含义**：E01a 的"300 题 × 3 次够用"只适用于相似条件之间的比较；比较不同权重（量化档，或推而广之不同模型）时，题目数要多得多，这个要求取决于对比本身的交互方差，需要逐个对比估计。

### 探索性发现（未预登记）1：AWQ 的过程层面损伤——行内 "Final Answer"
| | BF16 | FP8 | AWQ |
|---|---|---|---|
| 格式错误 / 100 次运行 | 0–2.9 | 1.0–4.3 | 21.4–36.7 |
| 至少一次格式错误的运行 | 0–0.6% | 0.2–0.7% | 3.7–6.0% |
| 搜索次数 | 1.83–1.88 | 1.72–1.78 | 1.58–1.63 |
| 达到步数上限 | 4.1–4.7% | 3.3–4.3% | 5.4–7.3% |
| 单次延迟（秒） | 1.84–2.91 | 1.18–1.44 | 0.88–1.10 |

- AWQ 的格式错误几乎都是同一种：把 "Final Answer:" 写在 Thought 那一行的中间，而解析器要求它在行首（判为"no Action or Final Answer line"），agent 于是继续循环。AWQ 缓存关时有格式错误的 126 次运行集中在 29 道题。
- **敏感性分析**：假设解析器也接受行内的 "Final Answer:"。这是精确的反事实：到第一次格式错误为止轨迹不变，宽松的解析器会在那一步结束。结果 AWQ 与 BF16 的差距从 −3.2 至 −5.0 pp 缩小到 −1.7 至 −3.3 pp（95% 区间全部包含 0）；FP8 和 BF16 基本不变。平均来看，**AWQ 的下降约三成来自这个格式问题**，其余约 2–3 pp 仍然存在。
- 解读：BF16 也有同样的失败，只是很少（BF16 有格式错误的 19 次运行里 17 次是这种），所以量化是放大了已有的失败模式，而不是带来新的失败，这与 2607.27275 在 τ²-bench 上的发现一致（他们的基准有容错额度，放大的失败被分数掩盖）。在我们的设置里，格式失败放大约 10 倍、少搜索、更常耗尽步数，分数也因此下降了一部分。这个结论依赖解析器的严格程度，属于评测设计本身的一部分。

### 探索性发现（未预登记）2：缓存开关本身改变贪心输出，程度取决于精度
同一个请求（同题、同臂、同种子，重复 0）分别在缓存关和缓存开的服务上运行（analysis/08_cross_launch.py）：

| greedy，每题第一次运行（300 题） | 任一步输出不同 | 动作序列不同 | 最终答案不同 | 第一步就不同 |
|---|---|---|---|---|
| BF16 | 75（25%） | 22 | 19（6.3%） | 24 |
| FP8 | 232（77%） | 95 | 51（17%） | 131 |
| AWQ | 46（15%） | 13 | 11（3.7%） | **0** |

- qwen 臂相同：第一次运行 BF16 74 / FP8 225 / AWQ 50（300 中）；同题之后的种子（复用该题已缓存的 prompt）BF16 142 / FP8 443 / AWQ 151（600 中）。
- 与同一缓存开服务内的分歧比较时要用同一口径（逐字比较；H1/H3 的 3–8% 是"答案或动作不同"，口径更粗）。同一服务内第一对重复（未命中 vs 命中）逐字不同的比例：BF16 61/300 = 20%、FP8 36/300 = 12%、AWQ 39/300 = 13%。所以 BF16 和 AWQ 换缓存设置的影响与服务内第一对的差别同一量级（20% vs 25%，13% vs 15%）；FP8 则是 6 倍（77% vs 12%）。准确率几乎不变（FP8 greedy 47.7% vs 48.2%）。
- 两种比较在第一步上的表现相反：AWQ 换缓存设置时第一步从不变，但服务内第一对有 18 题第一步就不同；FP8 换缓存设置时 131 题第一步就不同，服务内只有 3 题。论文图 3（figures/paper_fig3_cross_cache.png）。
- **跨启动可复现性（补测 dev_E01b_launch，2026-10-04 14:41–15:01）**：前 50 题 greedy，每个精度 × 缓存设置重新启动一次服务（与 E01b 相同的参数和 KV 块数）。FP8 和 AWQ 新启动加载的编译产物（vLLM torch_compile_cache）与 E01b 相同，**100/100 次运行与 E01b 逐字相同**，缓存关和缓存开都是如此。BF16 在 E00 与 E01a 之间（缓存开，两次启动，同一编译产物）40/40 逐字相同。所以上表是两条确定性计算路径之间的差别，不是启动噪声。
- 解读：这正是 2609.04748 测的量（开启缓存后 agent 轨迹改变的比例：16 位 36.2%、4 位 75.0%），而预登记的 H3 测的是同一缓存开服务内的同种子重复，两者不是一回事。我们的 BF16（25%）和 FP8（77%）与他们的量级相近，但 AWQ（INT4）反而比 BF16 少（15%），而且第一次运行的第一步从不受影响，所以不是"位数越低分歧越大"，更可能取决于内核（CUTLASS 分块 FP8 + 动态激活量化 vs Marlin W4A16，用 BF16 激活计算）。

### 探索性发现（未预登记）3：逐字复现需要同一个编译产物
- 补测里的 BF16 服务加载了**另一个**编译产物（b136b13b；E00/E01a 为 ab0f71ec）。原因是启动命令在 E01a 之后改过：加了 `--served-model-name`，以离线方式按快照路径加载模型，补测还加了 `--kv-blocks 1361`。这些改动在数值上本应无关，但改变了 vLLM 的编译配置。
- 结果，同样的前 50 题、同样的请求：缓存关时 10/50 题（20%）轨迹与 E01a 不同，其中 4 题第一步就不同，2 题最终答案不同；缓存开时第一次运行 10/50 题不同，算上两次重复共 6 题答案不同。新启动内部仍然确定（缓存关时两次重复 50/50 相同），这 50 题的准确率几乎不变（缓存关 64% vs 62%）。
- 对照：FP8 和 AWQ 用同一编译产物跨启动 0 差异；BF16 换编译产物后的差异（20%）和打开缓存的差异（25%）是同一量级。
- **方法含义**："关缓存时完全可复现"只在同一个服务构建（同版本、同启动配置、同编译产物）里成立。要复现别人的评测，除了引擎版本和解码参数，还要记录完整的启动命令和编译缓存；看似无关的参数（服务名、模型路径写法、KV 块数）也可能改变输出。我们这里能区分的只是"编译产物不同"这个整体，不能确定是哪一个参数起的作用。
- 偏离：补测的 BF16 条件因此不是与 E01a 的严格同条件比较（FP8/AWQ 是）；结果按上面的方式解读，不重跑。

## 结论
1. **关缓存时，三档精度在同一服务内都完全可复现**（H1），所以精度对比可以干净地按题目和种子分解。
2. **量化没有放大服务器内的缓存分歧**（H3 不成立）：开缓存时 FP8 和 AWQ 的同种子不一致率都不高于 BF16；分歧仍然集中在每题的第一对。
3. **精度对准确率的影响没有定论**（H4）：AWQ 一致地低 3–5 pp，但 Holm 校正后不显著，也不能判为等价；FP8 的效应随实验臂变化。AWQ 的下降约三成来自一个格式失败（行内 "Final Answer"），是过程层面的损伤。
4. **比较不同精度需要更多题目，而不是更多重复**：精度对比的交互方差比 E01a 的同类对比大 3–40 倍。300 题时检测 3 pp 的功效，BF16 vs AWQ 只有约 0.3–0.4，BF16 vs FP8 为 0.4–0.75；多跑几次几乎没有帮助。
5. **探索性**：打开缓存会改变 15–77% 题目的贪心轨迹（FP8 最多），但几乎不改变准确率；这是确定性计算路径之间的差别（同一编译产物跨启动 0 差异）。
6. **探索性**：逐字复现需要同一个编译产物：BF16 换了编译产物（启动命令改过）后，缓存关时 20% 的题目轨迹改变，与打开缓存的影响同一量级。评测报告应记录完整启动命令和编译缓存。
